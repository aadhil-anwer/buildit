# Stack

Decisions for building the app described in `app/PRODUCT.md` and the owner's
instructions. `design-docnew/` is the design reference (look and patterns),
not the feature list. Each line says what was picked and why. If you change one, change it here in the same commit.

## Decisions

| Area | Choice | Why |
| --- | --- | --- |
| App | Expo, managed workflow, development builds, Expo Router | No Mac needed (EAS Build); native modules for capture |
| Repo | npm workspaces monorepo: `apps/mobile`, `packages/core`, `supabase/` | One engine shared by app and Edge Function |
| Engine | `packages/core`, moved from `app/src/core` | Already handles polygon / L-shaped rooms, openings on walls, 23 furniture types, clearance, placement, RoomPlan import, with tests. `room3d.js` is the weaker prototype engine |
| 3D | React Three Fiber native (`@react-three/fiber/native`) on `expo-gl`, three.js | Scene is small (under ~30 bevelled boxes); same scene model as the engine |
| Tests (mobile) | `jest-expo` + `@testing-library/react-native` 14 (`render`, `fireEvent` are async: `await` them); tests sit next to the code | Per the Expo structure guide |
| Gestures | `react-native-gesture-handler` + Reanimated | Orbit, pinch, drag and rotate share one canvas and need explicit priority |
| Haptics | `expo-haptics` | Snap, lock, undo (handoff) |
| Navigation model | **2a Sheet**: room full-bleed, bottom sheet at 196 / 404 / 640 px | The room is the hero; Ask / Add / Item / Finishes fit as sheet tabs |
| State | Zustand; undo/redo as scene JSON snapshots | Already used in `app/` |
| Backend | Supabase: Postgres with RLS and column grants, auth (Apple + email), private storage, Edge Functions | Per PRODUCT.md |
| AI | Edge Function (Deno) → Claude tool use → **intents only**, streamed | The AI never returns coordinates, sizes or prices; `core` computes poses and facts |
| i18n | Typed `t()` (placeholder count checked at compile time), strings generated from the design doc, `expo-localization`; Arabic digits via our own mapping (Hermes `Intl` is uneven); a language change reloads the app | EN + AR with full RTL from day one |
| Fonts | `expo-font`: Cormorant Garamond 400/600, Lora 400/600, Amiri 400/700, Noto Naskh Arabic 400/600 | Each weight is its own `fontFamily`; RN does not synthesise weights |
| Design tokens | `apps/mobile/src/theme/tokens.ts` **generated by a script** from `design-docnew/_ds/classical-…/styles.css` (colours, 100–900 ramps, spacing scale at 1.15× density, radii, shadows), plus the handoff's additions (rust failing state, 3D material colours) | Never retyped by hand; the design system is the source |
| Icons | Lucide (`lucide-react-native`), 1.5 stroke, behind one `Icon` component | Handoff icon set |
| Web app (`app/`) | Frozen. Revived later as the web viewer for shared links | One editor, not two to keep in sync |

## Layout

```
apps/mobile/          Expo app (screens, theme tokens, primitives, R3F scene)
packages/core/        engine + rules + importers, plain TypeScript, no rendering
supabase/
  migrations/         append-only
  functions/agent/    Claude loop: request → intents (streamed)
  tests/              tenant-isolation and RLS SQL tests
design-docnew/        design doc + runtime (reference, not code to copy)
app/                  frozen Next.js prototype
```

## packages/core rules

- Pure TypeScript. No Node, DOM or React Native imports, so it runs in Hermes
  (app) and Deno (Edge Function).
- No WebAssembly. Hermes does not run it, which rules out Rapier, Clipper2-wasm,
  Manifold and OR-Tools in the app. Check before adding any geometry dependency.
- Allowed small pure-JS helpers when needed: `polygon-clipping` (free area,
  L-shapes), `flatten-js` or our own SAT test (rotated footprints), `rbush`
  (spatial index if rooms get large).
- Units are metres and degrees; scene conventions are documented in
  `packages/core/types.ts`.

### Bring over from the prototype (`room3d.js`), as behaviour, not code

- Rule statuses pass / tight / fail with weights (walkway 10, door swing 8,
  bed sides 6, storage front 6, window zone 5). Score = 100 − 1.4 × Σ penalty,
  minus 3 if the narrowest gap is under 100 cm.
- `optimize`: intent → up to 3 group moves; "show another option" excludes the
  first option's groups.
- `largestFree`: measured free area for the "nothing fits" state.
- Suggestions, restyle tables (`STYLES`) and "Suggested next", all returning
  intents.
- Find items by `type`, never by id (the prototype looks up `id === 'bed'`).
- Rotated pieces: the prototype uses axis-aligned bounds, which overstates a
  45° sofa. Use real rotated footprints.

## Capture

- LiDAR: `expo-roomplan` → RoomPlan JSON → `packages/core` RoomPlan importer
  (written; not yet verified with a real device export).
- Guided scan (non-LiDAR): a small custom Swift Expo module using ARKit plane
  detection and raycasts for corners, doors and windows. Not ViroReact, which
  is a large dependency for tap-to-mark.
- Type dimensions: plain form, same scan review screen.
- Android capture: later (ARCore).

## 3D in React Native: known constraints

- No `document.createElement('canvas')`: the plank floor texture and blob
  contact shadow ship as PNG assets.
- Only use drei helpers that don't need the DOM. Drag and rotate are our own
  gestures, not `TransformControls`.
- Look: orthographic camera, elevation 33°, azimuth 38°, ACES tone mapping at
  exposure 0.92, hemisphere + warm key light with soft shadows.
- Thumbnails and share images come from a GL snapshot of the scene.

## Performance budget

The app must stay smooth and must not heat or hang mid-range phones. Every
rule below has a number, so it can be checked.

### Target devices

- **Floor:** iPhone 11 (A13, 4 GB) for iOS; a Galaxy A-series class phone
  (about 4 GB RAM, mid-range GPU) when Android ships. Anything that runs well
  on the floor device runs well on the rest.
- Test on the floor device, not only on a Pro phone or the simulator.
  Simulators don't show real GPU or thermal behaviour.

### Budgets

| What | Budget |
| --- | --- |
| Frame rate while orbiting, dragging or gliding | 60 fps on the floor device; never below 50 for more than a moment |
| JS thread blocked by one task | ≤ 16 ms during interaction, ≤ 50 ms otherwise |
| Engine `check` (rules + score) for a 15-item room | ≤ 4 ms on the floor device |
| AI `optimize` / "another option" | ≤ 300 ms total, split into chunks of ≤ 8 ms (yield between chunks); progress narrated |
| Draw calls in the room scene | ≤ 150 |
| Triangles in the room scene | ≤ 150k |
| Textures | ≤ 1024 px per side, shared; total GPU texture memory ≤ 32 MB |
| Shadow map | One shadow-casting light, map ≤ 1024 (≤ 512 on the low tier) |
| Pixel ratio | Capped at 2 (1.5 on the low tier) |
| Live 3D canvases at once | **1**. Every other room image is a saved snapshot |
| Cold start to My rooms | ≤ 2.5 s on the floor device |
| App memory in the editor | ≤ 300 MB |
| Idle in the editor | No frames rendered; GPU and CPU near zero |

### How the 3D stays cheap

- `frameloop="demand"`: render only while something moves (orbit, drag,
  glide, sheet resize), then stop. An idle editor draws nothing, so the phone
  doesn't heat or drain the battery.
- Pause the canvas when the editor isn't the focused screen or the app is in
  the background.
- Animate in `useFrame` by changing object refs, never React state. The glide
  and camera smoothing must not re-render React components.
- Build geometry once and reuse it: one bevelled-box geometry per size class,
  shared materials per colour, instancing where pieces repeat (chairs,
  floor planks). Dispose geometry, materials and textures when a room closes.
- Prebaked assets: plank floor and blob shadow as small PNGs, not runtime
  canvases.
- Quality tiers chosen at launch from `expo-device` (year class, total memory):
  - **high:** soft shadows, pixel ratio 2, 1024 shadow map
  - **low:** blob contact shadows only, pixel ratio 1.5, 512 map, fewer bevel
    segments

  Drop to the low tier automatically if measured frame time stays above 20 ms.
- My rooms, Versions and Share show **snapshot images**, never live canvases
  (the prototype hit the browser's WebGL limit for this reason).

### How the engine stays off the critical path

- `check` runs after a drag ends or every ~100 ms while dragging, not on every
  touch move. Collision checks during a drag use only the moved piece.
- `optimize` is time-sliced: coarse grid first (20 cm steps), then refine
  around the best candidates (5 cm), yielding to the UI between chunks. The
  existing `improve.ts` already takes a `budgetMs`; keep that pattern.
- If a device still stalls, move the engine to a worker thread
  (`react-native-worklets` or a JS worker); `packages/core` is pure TS, so
  this needs no code changes in the engine.
- Heavy sorting, gap pairs and free-area grids reuse arrays between calls
  instead of allocating per candidate (garbage collection pauses cause dropped
  frames on Hermes).

### UI thread

- Sheet, chips, suggestion card and all screen motion run on Reanimated (UI
  thread), never `Animated` driven from JS or `setState` per frame.
- Zustand selectors pick only the fields a component needs; the 3D scene
  subscribes to items, not to the whole store.
- Long lists use FlashList.
- Fonts are loaded once at startup; only the weights listed above.

### How it's checked

- `packages/core` benchmark tests (Vitest) with time budgets for `check`,
  `gapsOf` and `optimize` on preset rooms. They run in CI, scaled by a factor
  for the CI machine, so regressions fail the build.
- Before a screen with 3D counts as built: run it on the floor device (or the
  closest available) with the React Native perf monitor and `r3f-perf`-style
  stats (fps, draw calls, triangles, memory), and record the numbers in the
  reply. If a budget is missed, fix it or log it in `OPEN_ISSUES.md`.

## AI flow

1. App sends the request text plus a scene summary to `functions/agent`.
2. A volatile RPC atomically checks and increments the per-account daily count
   (20/day, server setting). Over the limit → limit state with reset time.
3. Claude returns intents through tool use (e.g. `more_walking_space`,
   `add_rug`, `restyle:japanese`), streamed.
4. `packages/core` on the phone turns intents into poses, animates the glide,
   and reports measured facts (before → after).

The pose is computed on the phone: it's the user's own room and nothing priced
depends on it. The server only enforces the usage cap.

## Data (Supabase)

`rooms`, `room_versions` (scene jsonb), `scans` (private bucket, short-lived
signed URLs), `ai_usage_daily`, `audit_log`; `products` and `shops` later.
Deny by default, column grants, ownership re-checked inside definer
functions, tenant-isolation test extended with every owned table (see
`CLAUDE.md`).

## Language switching

RTL in React Native (`I18nManager.forceRTL`) applies only after a reload. The
EN | ع toggle saves the choice and reloads the app (`Updates.reloadAsync`).
People rarely switch, so a reload is acceptable.

## Open

- `app/src/agent/tools.ts` must be audited: tools must take intents, not
